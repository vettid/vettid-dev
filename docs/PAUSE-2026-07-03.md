> **NOT ON GITHUB (owner decision 2026-07-03):** the COST-PAUSE commit is
> deliberately not pushed to `origin` (GitHub) for now. It exists locally and
> as a backup on the local Gitea (`git.al.liebl.us/al/vettid-dev`, remote

> GitHub `origin/main` — anyone deploying from a fresh GitHub clone would
> resurrect the NAT gateway, endpoints, and enclave capacity. Reconcile with

VettID development is paused. The vettid.dev website and the public leash demo
remain live; everything else is shut down to cut the AWS bill from ~$598/mo to
~$70–80/mo. There were no active users — JetStream state on the NATS instances
was discarded, but **vault data (S3 `vettid-vault-data-*`), KMS keys, all
DynamoDB tables, Cognito pools, SSM parameters, and AMIs are preserved.**

## Restore procedure (~30–45 min)

1. **Revert the pause commit** (touches only `cdk/lib/nitro-stack.ts`):
   ```bash
   cd vettid-dev
   git log --oneline --grep COST-PAUSE   # find the pause commit
   git revert <pause-commit> && git push
   ```
2. **Set the synth-time secret** (required for any cdk command in this app):
   ```bash
   export DEVICE_ATTESTATION_SECRET=$(aws secretsmanager get-secret-value \
     --secret-id vettid/device-attestation-secret --query SecretString --output text)
   ```
3. **Redeploy NATS first** (enclave parent needs `nats.vettid.dev` at boot):
   ```bash
   cd cdk && npm run build && npx cdk deploy VettID-NATS --exclusively
   ```
   Uses the pre-built AMI from `/vettid/nats/ami-id`. JetStream starts empty —
   streams are recreated by normal operation.
4. **Redeploy Nitro** (restores NAT GW, interface endpoints, ASG desired 1 —
   enclave instance boots the last-deployed enclave AMI):
   ```bash
   npx cdk deploy VettID-Nitro --exclusively
   ```
   If the parent wedges on NATS connect after `parent.yaml` is written, restart
   it via SSM: `systemctl restart vettid-parent` (known parent-yaml race).
5. **Start TURN instances** (EIPs/DNS unchanged):
   ```bash
   aws ec2 start-instances --instance-ids i-03b66ffe201dc3510 i-0afd9e462dfddc75d
   ```
6. **Re-enable EventBridge rules** (the cdk deploys above re-enable the ones in
   their own stacks; verify all):
   ```bash
   aws events list-rules --query 'Rules[?State==`DISABLED`].Name'
   aws events enable-rule --name <each>
   ```
7. **Verify**:
   - `curl https://api.vettid.dev/vault/pcrs/current` returns the current PCR set
   - `enclave/scripts/verify-deployment.sh` (attestation + health)
   - Device-approval / login with a test phone. If sessions act stale
     (JetStream state was lost), run `vettid-android/scripts/decommission-vault.sh`
     and re-enroll the phone.

## Gotchas discovered while pausing (why the plan is shaped this way)

- **Do NOT `cdk destroy VettID-Nitro` or `VettID-Turn`**: fixed-name retained
  resources (`vettid-vault-data-*`, `vettid-pcr-manifest-*`,
  `vettid-ssm-session-logs-*` buckets; `vettid/turn-shared-secret`) would
  collide on redeploy.
- **Do NOT run `npm run deploy` / deploy-all while paused** — deploying all
  stacks is fine only *after* the pause commit is reverted; with the pause
  commit in place it would just re-assert the paused state, but a stale
  checkout from before the pause would resurrect full capacity.
- Every cdk command needs `DEVICE_ATTESTATION_SECRET` exported (synth-time
  check in `vault-stack.ts`); source it from Secrets Manager as in step 2 —
  never generate a fresh value, that would rotate the deployed Lambda secret.
- **`VettID-NATS` deletion needed 3 attempts** because of resources created
  outside CloudFormation (relevant if the stack is ever torn down again):
  1. the NATS lifecycle Lambda writes a `cluster.internal.vettid.dev` A record
     into the private zone (blocked `HostedZoneNotEmptyException` — delete the
     record, retry), and
  2. the AMI build script leaves a `vettid-nats-build-sg` security group in
     the VPC (blocked "vpc has dependencies" — delete the SG, retry).
  Both get recreated by normal operation/builds after restore; nothing to fix.
